# 메이플랜드 보스 파티 정산

React + Vite를 사용하는 JavaScript 프로젝트입니다.
서비스 이름은 **메랜정산**입니다. 홈 화면에서 정산 시작하기를 누르면 보스별 메뉴가 열립니다.
자쿰(노멀)·자쿰(카오스) 파티 정산과 자쿰(노멀) 외판공대 정산을 사용할 수 있습니다.
아이템 검색은 임시 목록이며 직접 입력도 가능합니다. 실제 메이플랜드 API는 연결하지 않았습니다.
정산방 생성·입장·공유 링크와 Supabase 서버 코드가 추가되었습니다. **실제 Supabase 연결 및 배포는 아직 하지 않았으며 기본값은 로컬 모드**입니다. 연결 방법은 [Supabase 설정 안내](supabase/SETUP.md)를 참고하세요.
**정산 저장**으로 저장한 기록은 새로고침하거나 브라우저를 다시 열어도 유지됩니다.
저장 전 입력 내용은 같은 탭의 메뉴 이동 동안만 유지됩니다.

## 실행 방법

VS Code에서 이 폴더를 연 뒤, 상단 메뉴의 **터미널 → 새 터미널**을 선택하세요.

처음 설치하거나 다른 컴퓨터에서 시작할 때 필요한 패키지를 설치합니다.

```sh
npm install
```

개발 서버를 실행합니다.

```sh
npm run dev
```

브라우저에서 http://localhost:5173 에 접속하세요.
해당 포트를 다른 프로그램이 사용 중이면 터미널에 표시된 Local 주소로 접속하세요.
서버가 실행되는 동안 터미널을 열어 두세요. 종료하려면 Ctrl+C를 누르세요.

`src/App.jsx`를 수정하고 저장하면 브라우저에 자동 반영됩니다.

- `src/settlement/calculations.js`: 공통 5% 수수료 및 균등 분배 계산
- `src/settlement/settlement.css`: 새 정산 화면의 반응형 스타일
- `src/settlement/useHashRoute.js`: 주소와 브라우저 뒤로 가기에 따른 화면 전환
- `tests/`: 기존 계산, 새 분배 규칙, 저장·인증, 메뉴 렌더링, React 화면 조작 테스트
- `src/main.jsx`: React 앱을 시작하는 파일
- `src/index.css`: 디자인 토큰, 공통 버튼·카드 스타일 및 반응형 레이아웃

- `package-lock.json`: 설치한 패키지의 버전을 기록하는 파일
- `.oxlintrc.json`: 코드 검사 설정
- `.gitignore`: Git에서 제외할 파일과 폴더 설정

## 정산 사용 방법

1. 홈의 **정산 시작하기**를 누르고 보스와 정산 방식을 선택합니다.
2. **파티 보스정산**: 닉네임으로 파티원을 추가하고, 아이템을 여러 개 등록합니다. 각 아이템의 이름과 판매금액을 입력하면 수수료, 총 수익, 파티원별 정산금이 즉시 계산됩니다. 파티원과 아이템을 삭제할 수도 있습니다.
3. **외판공대 정산**: 1트·2트의 판매금액을 입력하고 포함할 항목을 체크합니다. 처음에는 모든 항목이 제외되어 있습니다. 체크를 해제하면 금액은 남아 있지만 해당 항목은 수익과 수수료 합계에서 제외됩니다.
4. 외판공대에도 이름으로 공대원을 등록합니다. **공대원 수 → 인원 적용**으로 임시 이름을 일괄 등록한 뒤 수정할 수도 있습니다. 인원을 줄일 때는 삭제할 인원 수를 확인합니다.
5. 1트·2트 리저 비용은 각각 해당 트라이의 실제 수익에서 한 번만 차감됩니다. 각 트라이의 개인별 정산금과 1트+2트 합계가 표시됩니다.
6. 자쿰(카오스) 외판공대 메뉴는 준비 중 안내를 표시합니다. 크림슨우드와 혼테일은 예정 표시만 제공합니다.

모바일에서는 정산 결과가 입력 영역 아래에 표시됩니다. 외판공대 판매표는 표 영역 안에서 좌우로 스크롤할 수 있습니다.

## 현재 계산 기준

추가된 `50% 차감 (흰경/공대 운영금)`은 해당 트라이의 기본 몫 절반을 공대 운영금으로 이동하며 재분배하지 않습니다. 기존 흰경과 사망 차감은 이전 규칙을 유지합니다. 운영금은 별도 장부나 추가 비용이 아니라 개인 몫에서 이동한 금액입니다. 전체 정산금은 개인 지급 합계 + 운영금 + 잔여 메소이며, 실제 정산 전 제외 차감금은 별도로 표시합니다. 개인 지급액과 운영금 기여액은 각각 1메소 단위로 내리고 남은 금액을 잔여 메소에 보존합니다.

운영금은 트라이·전체 결과와 개인별 기여액에 저장되며 서버도 다시 계산합니다. 기존 기록에 해당 옵션이 없으면 원본 결과 구조를 유지하고 화면에는 운영금 0을 표시합니다. 공대 운영금 장부와 확성기 지원금은 여전히 제공하지 않습니다.

- 모든 판매에 수수료 5% 적용: 판매금액 × 0.05
- 실제 받은 금액: 판매금액 − 수수료
- 외판공대 최종 정산금: 포함 항목의 실제 받은 금액 합계 − 1트·2트 리저 총 비용
- 기본값은 트라이별 균등 분배이며, 개인 비율·사고 설정에 따라 변경됩니다. 개인 금액은 트라이별로 1메소 단위로 내림하고 **분배 후 잔여 메소**를 별도 표시합니다.
- 수수료 자체는 반올림하지 않고 소수 둘째 자리까지 정확히 계산
- 금액은 0 이상 정수, 최대 12자리. 인원은 1~1,000명
- 인원이 없거나 리저 비용이 실제 수익보다 크면 1인당 정산금을 표시하지 않고 안내

예: 7,000,000 메소 판매 → 수수료 350,000 → 실제 수익 6,650,000 메소.

기존 PDF는 판매 항목, 1트·2트 구조와 결과 표의 구성만 참고했습니다.
과거 1.8% 수수료, 수작, 판매 조건별 자동 선택, 별도 아이템 분배금, 공대 운영금과 확성기 관련 기능은 구현하지 않았습니다.

## 비율 조정과 사고 처리

- 공통 명단을 등록한 뒤 **1트·2트 개인별 정산표의 참여 체크**로 각 트라이의 인원을 정합니다. 이름은 명단에서 수정하며, 같은 사람의 1트+2트 금액은 내부 ID로 연결됩니다.
- 각 트라이에서 마지막으로 **적용**한 한 명의 기본 비율을 유지하고, 나머지 참여자는 남은 비율을 균등하게 나눕니다. 예: 6명 중 한 명을 30%로 설정하면 나머지는 14%입니다.
- **기본 비율 → 사망 차감 → 재분배** 순서입니다. 직접 조정한 비율은 사고 차감 이전 기준이며, 100% 차감된 사람에게 직접 조정으로 금액이 돌아가지 않습니다.
- 100% 차감은 해당 트라이의 기본 몫 전부, 50% 차감은 기본 몫 절반을 차감합니다. 차감금은 해당 트라이의 사고 없는 **1파티** 참여자에게만 균등 재분배합니다. 기타 참여자는 재분배 대상이 아닙니다.
- 받을 정상 1파티 참여자가 없으면 분배를 확정하거나 저장할 수 없습니다. 해당 트라이의 설정을 확인해주세요. 이 경우 임의로 새로운 분배 규칙을 적용하지 않습니다.
- 화면의 퍼센트는 소수 둘째 자리 표시 합계가 100.00%가 되도록 미세 보정합니다. 실제 금액은 표시용 반올림 이전의 정확한 비율로 계산합니다.
- 리저 비용이 해당 트라이의 실제 수익을 초과하는 경우에도 분배와 저장을 막고 안내합니다.

## 저장·조회·수정

1. 정산 날짜를 선택하고 **정산 저장**을 누릅니다.
2. 8~128자의 수정 비밀번호와 확인값을 입력해 저장합니다.
3. 상단 **지난 정산 내역**에서 정산 날짜순 목록과 상세 내용을 조회합니다.
4. 상세 화면의 **수정하기**에서 비밀번호를 확인하면 편집할 수 있습니다. **수정 내용 저장**은 같은 기록을 갱신하며, **수정 취소**는 원래 기록을 유지합니다.
5. 수정 화면을 떠나거나 새로고침하면 다시 비밀번호 확인이 필요합니다. 다른 탭에서 먼저 수정한 경우 오래된 편집 화면이 최신 기록을 덮어쓰지 못하도록 차단합니다.

localStorage 키는 `meraen-settlement.records.v1`입니다. 저장 기록에는 입력값, 사고·기본 비율 설정, 계산된 최종 비율·수수료·비용·개인 금액을 함께 보존합니다. 금액 내부 계산은 BigInt를 사용하고 저장할 때 문자열로 변환합니다.

비밀번호는 기록마다 다른 16바이트 소금값을 사용해 **PBKDF2-SHA256 600,000회, 256비트**로 처리합니다. 평문 비밀번호는 코드나 저장 기록에 남기지 않습니다. 구현은 [Web Crypto PBKDF2 안내](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveBits)를 따릅니다.

이 방식은 로컬 UI의 수정 보호이며 서버 인증이 아닙니다. 같은 브라우저 데이터나 개발자 도구에 직접 접근하는 사람을 차단하지는 못합니다. 배포 시에는 `records.js`와 `auth.js`의 기능을 서버 저장·인증으로 교체해야 합니다. 비밀번호 분실 복구는 지원하지 않습니다.

기록은 같은 브라우저·같은 사이트 주소에서만 조회할 수 있습니다. 다른 기기와 자동 공유되지 않으며, 브라우저 데이터를 삭제하면 기록도 삭제됩니다. 저장 차단·용량 부족·손상된 데이터가 있으면 오류를 표시하고 기존 기록을 덮어쓰지 않습니다.

## 최근 외판공대 기록 불러오기

외판공대 화면에 두 개의 **최근 기록 불러오기** 버튼이 있습니다.

- 공대원 아래: 최신 **자쿰(노멀) 외판공대** 저장 기록의 이름·파티 구분만 복사합니다. 현재 명단을 교체하고 참여/사고/기본 비율 설정은 초기화합니다. 판매 내역과 리저 비용은 유지합니다.
- 리저 비용 아래: 같은 기준의 기록에서 1트·2트 비용만 복사하고 합계는 자동 계산합니다. 명단과 판매 내역은 유지합니다.

최근 기준은 정산 날짜가 아닌 **마지막 저장 시각**입니다. 기록을 수정 저장한 경우 그 저장도 포함합니다. 불러온 값의 변경은 원본 기록에 영향을 주지 않습니다.

## 테스트 범위

`npm test`는 기존 수수료 계산, 균등/직접 비율, 50%·100% 사고, 복수 사고, 1파티 재분배, 트라이 간 독립성, 100% 비율 합계, 잔여 메소 보존, 영속 저장, 기록 정렬, 비밀번호 검증, 수정 권한, 동시 수정 충돌, 최근 기록 복사를 검사합니다.

Happy DOM 기반 React 통합 테스트는 실제 컴포넌트에서 등록·입력·저장·재마운트·조회·틀린/맞는 비밀번호·수정 저장·최근 기록 불러오기까지 조작합니다. 이는 브라우저의 실제 픽셀 배치를 확인하는 시각 테스트와는 별개입니다.

## 정산방과 카오스 파티 확장

### 판매 진행 및 정산방 관리

파티 보스정산은 이름만으로 아이템을 저장할 수 있습니다. 빈 금액은 **판매 전**으로 표시하며 합계에 기여하지 않습니다. 금액을 입력하면 **판매 완료**가 되고 기존 5% 수수료 계산에 반영됩니다. 명시적으로 입력한 `0`은 빈 입력과 구분합니다. 상태는 저장된 금액에서 판단하며 새 파티 아이템 저장에는 `saleStatus`도 보존합니다. 서버 저장 시 금액을 기준으로 상태를 다시 맞춥니다. 외판공대 판매표에는 이 상태 기능을 적용하지 않습니다.

`src/settlement/bossItems.js`에서 노멀/카오스 목록을 각각 관리합니다. 현재 두 목록은 기존 임시 아이템 목록을 복사한 것이며 실제 드롭 확정 목록을 새로 추가하지 않았습니다. 메이플 API 연결은 없습니다. 검색 선택과 직접 입력을 모두 사용할 수 있습니다.

정산방 생성 시 17개 아이콘 중 선택할 수 있고 기존 방의 누락값은 🍁으로 표시합니다. `우리 공대 정산방`은 이 브라우저에서 생성·방문한 최근 30개 방을 보여줍니다. 방 코드만 별도 로컬 키에 기억하고 공개 요약은 서버에서 조회해 최근 정산 날짜순으로 정렬합니다. 기록이 없으면 생성 날짜를 사용합니다. 다른 기기에서는 링크나 코드로 입장하면 그 기기의 목록에 추가됩니다. 전체 서비스의 방을 공개하는 목록이 아닙니다.

관리자 확인 후 **정산방 관리 → 정산방 삭제**에서 경고를 확인하고 비밀번호를 다시 입력합니다. 서버에서 비밀번호와 유효한 방 전용 세션을 확인하며, DB 트랜잭션에서도 세션을 재확인합니다. 삭제하면 해당 방의 정산 기록과 관리자 세션이 FK cascade로 함께 삭제됩니다. 만료된 세션은 관리자 확인을 다시 한 뒤 삭제할 수 있습니다. 삭제는 복구할 수 없습니다.

추가 SQL은 `supabase/migrations/202609160001_room_icons_delete.sql`입니다. nullable 아이콘 열과 서버 전용 함수만 추가하며 기존 방을 일괄 갱신하지 않습니다. 정산 계산·수수료·차감·운영금 규칙은 유지됩니다.

- 상단 **정산방**에서 방 이름과 관리자 비밀번호를 정하고 방을 만듭니다. 6자리 코드 또는 공유 링크로 입장할 수 있습니다.
- 방 하나에 여러 정산을 저장합니다. 읽기는 비밀번호 없이 가능하고, 새 정산 저장과 수정에는 방 관리자 권한이 필요합니다. 기존 개별 정산의 비밀번호 보호는 유지됩니다.
- 방 안의 최근 외판공대 명단·리저 비용은 해당 방의 최근 노멀 외판공대 기록에서 가져옵니다.
- 카오스는 1~5파티 및 기타참여자 분류와 필터를 제공합니다. 파티별 권장 인원은 6명이며 강제하지 않습니다. 전체 공대의 1트·2트 구조는 유지합니다.
- 위 사고 처리 설명의 1파티 규칙은 노멀에 해당합니다. 새 카오스 정산은 차감금을 사망자의 **같은 파티 정상 참여자**에게만 재분배합니다. 다른 파티의 배분액은 바뀌지 않습니다. 받을 사람이 없는 파티는 설정을 고치기 전 저장을 막습니다.
- 이전 버전 기록은 원본을 유지한 채 조회합니다. 편집할 때 이전의 기타참여자 구분을 새 구조로 변환합니다.
- 금액 입력과 결과에 `100만`, `8억 5천`, `약 1억 4,166만` 같은 보조 표기를 제공합니다. 계산은 BigInt 기반 정확한 값을 유지합니다.

추가된 파일은 `src/rooms/`(방 UI·서비스·저장 어댑터), `server/`(서버 요청·DB 처리), `supabase/`(테이블·Edge Function), `src/settlement/koreanMeso.js`(금액 표기), `.env.example`입니다. 기존 홈 구성은 유지하고 헤더에 방 메뉴를 추가했습니다.

테스트는 기존 34개와 신규 18개, 총 52개입니다. 신규 검증에는 방 코드 중복, 공개 조회, 관리자 인증·만료·권한 범위, 수정 충돌, UI 조작, 카오스 파티 내부 재분배, 한글 금액, 실제 PostgreSQL 엔진의 테이블 접근 차단 및 트랜잭션을 포함합니다. 실제 Supabase 배포와 브라우저 픽셀 검사는 별도입니다.

## 공개 정산방 목록과 이름 변경

**모든 정산방**은 개인 방문 목록과 분리된 Supabase 공개 목록입니다. `room-api`의 `list-all` → `room_api_list_all` 경로로 30개씩 조회하며, 최근 정산 기록의 `updated_at`(기록이 없으면 방 `created_at`) 내림차순입니다. 방 화면 진입·창 복귀·현재 방 변경 시 새로 조회합니다. 개인 방문 목록의 코드 저장 및 최근 30개 제한은 그대로 유지합니다.

**정산방 이름 수정**에서 생성 시와 동일한 아이콘도 선택할 수 있습니다. 이름만·아이콘만·둘 다 수정할 수 있으며 서버는 관리자 비밀번호와 방 전용 세션을 검증합니다. SQL 트랜잭션도 세션 만료를 확인하고 `room_name`·`icon`만 갱신합니다. 정산·비밀번호 해시·방 코드는 수정하지 않습니다. 아이콘을 생략한 기존 클라이언트 요청은 현재 아이콘을 유지합니다.

`202609170001_room_directory_access.sql`까지 적용하고 최신 `room-api`와 프런트엔드를 함께 배포해야 합니다. 공개 목록 RPC는 service_role만 실행할 수 있고 anon/authenticated의 직접 DB 접근 권한을 추가하지 않습니다. 공개 응답은 방 ID·이름·아이콘·날짜만 포함하며 **방 코드와 정산 상세는 포함하지 않습니다**. 기존 아이콘 누락값은 🍁으로 표시합니다.

공개 카드의 입장 버튼은 코드 입력 모달을 엽니다. `enter` API가 선택한 방 ID와 입력한 6자리 코드의 일치를 확인한 뒤에만 상세 정산을 조회합니다. 다른 방의 유효한 코드도 거부합니다. 코드가 포함된 기존 공유 링크는 `read` API를 통해 그대로 입장합니다. 반복적인 코드 조회에는 서버 요청 제한이 적용됩니다.

개인 방문 목록은 해당 브라우저의 localStorage 코드만 사용합니다. 공개 목록 조회·카드 클릭·틀린 코드 입력은 방문 기록을 만들지 않습니다. 방 생성 또는 올바른 코드로 상세 조회에 성공한 경우에만 기록합니다. 기존 방문 기록은 임의로 삭제하지 않습니다.

요청한 특정 방의 코드 변경 SQL은 `supabase/operations/20260916_room_code_18PMMM.sql`에 별도로 보관합니다. 일반 migration에 포함하지 않습니다. 지정된 기존 방만 갱신하고 코드 충돌 또는 정산/인증 정보 변경이 감지되면 롤백합니다.

## 이후 메이플랜드 API 연결

임시 아이템 목록은 `src/settlement/calculations.js`의 `MOCK_ITEMS`이며 검색 입력 UI는 `src/settlement/SettlementEditor.jsx`에 있습니다. 별도의 아이템 API 어댑터를 추가하고 이 검색 데이터 공급 부분을 연결하면 됩니다. 수수료·비율 계산과 정산방 DB 코드를 검색 API 코드에 섞을 필요는 없습니다.
